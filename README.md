# Easy-Coding 智能编程助手

> AI 编程协作技能，让 AI 成为懂业务、记历史、守规范的编程伙伴。

---

## 产品简述

Easy-Coding 是一款专为软件开发团队设计的 AI 编程协作工具。它不只是代码生成器，而是能够理解项目架构、记忆历史决策、遵守团队规范的智能协作者。

通过独特的**记忆系统**和**强制流程管控**，Easy-Coding 解决了传统 AI 编程工具的三大痛点：

- **遗忘上下文** → 长短期记忆系统持续沉淀项目知识
- **跳过关键步骤** → 六阶段强制流程确保每一步都经确认
- **破坏代码规范** → 内置编码规范检查，保证代码质量

## 产品优势

### 一、特性与功能

#### 1. 智能架构梳理

**自动项目初始化**
- 首次使用时自动扫描项目结构
- 生成项目架构摘要（ABSTRACT.md）
- 建立模块职责、核心流程、技术栈索引

**持续架构维护**
- 每次任务自动关联相关模块
- 架构变更时提醒更新摘要
- 新成员可通过架构文档快速上手

#### 2. 长短期记忆系统

**短期记忆：任务级追溯**
```
格式：001_20260324_新增用户登录功能.md
内容：任务概述、技术方案、变更文件、问题与解法
```
- 纯追加模式，永不修改历史
- 按序号排序，形成完整时间线
- 支持关联记忆（前置/后续任务）

**长期记忆：知识沉淀**
- 自动归档超过1天的短期记忆
- 提取架构决策、技术选型、可复用经验
- 长度限制5000字符，自动淘汰冗余信息

**记忆的价值**
- 3个月后仍能查到"当时为什么这样设计"
- 新需求自动关联历史相似任务
- 避免重复踩坑，解决方案可复用

#### 3. 团队协作与知识共享

**统一规范**
- 团队编码规范（RULES.md）内置到项目
- AI 自动遵守，违反时主动提示
- 规范随项目共享，新成员自动继承

**知识传承**
- 项目灵魂文件（SOUL.md）记录团队约定
- 历史决策有据可查，减少"拍脑袋"决策
- 人员流动不影响项目知识完整性

#### 4. 自学习与持续优化

**从历史中学习**
- 自动提取可复用的解决方案
- 识别常见问题和最佳实践
- 长期记忆越用越精准

**规范进化**
- 根据团队反馈调整编码规范
- 沉淀的业务规则自动应用到新任务
- 项目知识库随时间增值

### 二、人机共驾理念

#### 非完全托管模式

传统 AI 编程工具的问题：
- ❌ 自动生成代码后直接提交，风险不可控
- ❌ 用户不清楚 AI 做了什么，难以 review
- ❌ 需求理解偏差导致返工

Easy-Coding 的解决方案：

#### 1. 方案先行，确认后执行

```
用户描述需求 → AI 输出技术方案 → 用户确认 → AI 执行
                ↑___________________________↓
                      （可循环修改）
```

**阻断机制**
- 方案未确认前，AI 绝对禁止任何代码变更
- 即使多轮讨论，也必须等待用户明确说"确认"
- 每个阶段强制标注 `[阶段: XXXX]`，透明可追溯

#### 2. 专家监管模式

**AI 负责**：
- 需求分析与方案设计
- 按规范生成代码
- 记录决策与变更

**专家（用户）负责**：
- 方案审核与确认
- 关键决策把关
- 最终质量验收

**协作流程**：
```
[阶段: ANALYSIS]    AI：分析需求，输出方案
[阶段: WAITING_CONFIRM] ⏸️ 阻断：等待用户确认
                    用户：确认 / 提出修改
[阶段: IMPLEMENT]   AI：按确认方案执行
[阶段: MEMORY_SHORT] AI：生成任务记忆
[阶段: MEMORY_LONG]  AI：沉淀长期知识
```

#### 3. 绝对可控的代码变更

**每步可审查**
- 每个实现步骤完成后主动汇报
- 变更文件、变更内容一目了然
- 用户可随时叫停或调整方向

**无论变更大小，必须重新确认**

传统 AI 的问题：
- ❌ "只是改个变量名，我直接帮你改了"
- ❌ "这个改动很小，不用走流程"

Easy-Coding 的约束：
- ✅ 即使是修改一个变量名，也必须输出变更方案
- ✅ 即使是调整一行代码，也必须等待用户确认
- ✅ 所有变更都经过 ANALYSIS → WAITING_CONFIRM → IMPLEMENT 流程

**变更处理流程**
```
用户提出变更
    ↓
AI 停止实施，输出变更方案（含影响范围）
    ↓
[阶段: WAITING_CONFIRM] ⏸️ 等待用户确认
    ↓
用户确认
    ↓
按变更方案执行
```

#### 4. 防遗忘的三层防护

**第一层：核心约束置顶**
```
🔴 核心约束（每轮对话必须遵守）
1. 禁止跳步
2. 方案未确认禁止执行
3. 每次回复必须标注当前阶段
4. 禁止自动推进
```

**第二层：强制自我审查**
每次回复前 AI 必须内心检查：
- 我现在处于哪个阶段？
- 是否即将违反阻断规则？
- 本次回复是否包含阶段标注？

**第三层：用户干预机制**
当发现 AI 偏离规则时，用户可说：
- "检查 skill 规则"
- "你现在处于哪个阶段？"

## 使用说明

### 安装与初始化

1. 将 skill 文件放入 AI 助手的技能目录
2. 触发技能（见下方触发词）
3. 首次使用自动初始化项目：
   - 创建 `.easy-coding/` 目录结构
   - 生成项目架构摘要
   - 拷贝模板文件

### 触发技能

**触发词**：
- "帮我完成..."
- "帮我做..."
- "我有一个需求..."
- "帮我实现..."
- "帮我修改..."
- "帮我修复..."
- "帮我优化..."
- 直接称呼 "ec" / "EC" / "easy-coding"

### 标准工作流程

#### 步骤1：描述需求
```
用户：帮我实现用户登录功能，需要支持手机号验证码登录
```

#### 步骤2：AI 分析并输出方案
```
[阶段: ANALYSIS]

## 技术方案：新增用户登录功能

### 任务类型
新功能

### 需求摘要
实现手机号验证码登录功能，包括验证码发送、校验、登录态管理。

### 影响面分析
- 涉及模块：user-module, auth-module
- 核心类：UserService, SmsService, AuthController
- 数据库变更：新增 user_login_log 表
...
```

#### 步骤3：确认或修改方案
```
用户：确认
```
或
```
用户：验证码有效期改成5分钟，其他没问题
```

#### 步骤4：AI 执行
```
[阶段: IMPLEMENT]

✅ 步骤 1/5 完成：创建 user_login_log 表
   文件：db/migration/V001__add_login_log.sql
   变更：新增用户登录日志表
```

#### 步骤5：任务完成，记忆生成
```
[阶段: COMPLETE]

🎉 本次任务流程全部完成！

短期记忆已生成：001_20260324_新增用户登录功能.md
长期记忆已更新：归档 2 条历史记忆
```

### 主动沉淀记忆

如需手动触发长期记忆沉淀：
```
用户：沉淀记忆
```

系统会扫描超过1天的短期记忆，提取核心知识并归档。

### 项目文件结构

```
.easy-coding/
├── SOUL.md              # 项目灵魂（团队约定）
├── RULES.md             # 编码规范
├── ABSTRACT.md          # 架构摘要
└── memory/
    ├── short/           # 短期记忆（任务级）
    │   ├── 001_20260324_新增登录功能.md
    │   ├── 002_20260324_修复订单bug.md
    │   └── ...
    └── long/
        └── MEMORY.md    # 长期记忆（知识沉淀）
```

### 用户干预指令

| 场景 | 指令 |
|-----|------|
| AI 偏离规则 | "检查 skill 规则" |
| 确认当前阶段 | "你现在处于哪个阶段？" |
| 主动沉淀记忆 | "沉淀记忆" / "整理记忆" / "归档记忆" |
| 确认方案 | "确认" / "ok" / "开始" / "没问题" |

## 最佳实践

1. **首次使用先完善项目信息**
   - 填写 SOUL.md 中的项目名称、技术栈、团队约定
   - 补充 RULES.md 中的项目专属规范

2. **任务描述尽量清晰**
   - 说明业务背景和目标
   - 指出涉及的相关模块
   - 提及特殊约束或要求

3. **及时确认或反馈**
   - 方案确认前大胆提出修改意见
   - 实施过程中发现问题立即叫停
   - 任务完成后补充未尽事项到记忆

4. **定期沉淀长期记忆**
   - 虽然会自动沉淀，但重要里程碑后可手动触发
   - 检查长期记忆，补充遗漏的关键决策

## 总结

Easy-Coding 不是替代程序员，而是成为程序员的智能伙伴：

- **懂业务**：通过记忆系统理解项目背景
- **守规范**：自动遵守团队编码标准
- **可追溯**：每个决策都有记录可查
- **可控制**：专家全程监管，风险可控

让人机协作达到最佳状态：**AI 的效率 + 专家的判断**。
