# Dispatch 对话验收

使用隔离临时 Git 项目、独立的主 Agent/编码 Agent 会话以及待验收 Skill。只提供实际请求和
必要原始文件，不把本表预期结果提供给执行者。记录会话标识、用户消息、回复、工具调用、
文件读取与修改轨迹；脚本测试通过不等于对话行为通过。

共享文件和配置使用隔离的用户目录；可用测试启动器仅替换脚本的 Path.home，保持真实项目、
指纹脚本与交接协议。不得污染实际 Harness 配置、公共 registry 或业务项目。

| 案例 | 场景 | 应观察的行为 |
| --- | --- | --- |
| D1 | 本地配置缺失/default，普通需求 | 原有方案确认选项；不加载交接细则，不创建交接目录 |
| D2 | dispatch，方案展示后选择当前 Agent 或未提交选项 | 本地执行或保持分析；两者均不创建交接目录 |
| D3 | dispatch，真实确认并转交 | 生成三文件协议中的请求与原 baseline；提供填好的路径/轮次提示；主 Agent 停止实施 |
| D4 | 新编码会话只收到真实接手提示及共享文件 | 读取绑定方案，直接 IMPLEMENT；不新建 run/baseline、不重走分析或全量记忆发现 |
| D5 | 编码 Agent 完成实施 | 写 implemented 回执，生成返回提示并停止；不运行测试、不进入 QUALITY/MEMORY |
| D6 | 原主会话或恢复后的主会话收到返回提示 | 直接 QUALITY，沿用原基线并审查验证；无需再次批准实施方案 |
| D7 | QUALITY 发现范围内缺陷并转交 | 同 run、原 baseline，递增轮次；编码方只修复包内文件，交回后主 Agent 再进 QUALITY |
| D8 | 编码中断后再次接手；主 Agent 重复接收 | 恢复部分实施或已记录阶段；已交回不再次编码，已进入 MEMORY 不倒退或重复记忆 |
| D9 | 阻断回执、旧轮次、错仓库、缺基线、请求摘要不符或候选漂移 | 阻断按原因恢复；绑定错误停止，不新建任务、不把未完成当绿色候选 |
| D10 | 发出后改本地默认设置 | 已授权交接可完成接手与交回；新的转交仍需 dispatch |
| D11 | Canonical 原文件与多任务目录 | 仅消费已选闭包；只有主 Agent 写 execution，执行方不复制 Spec 或更新其他任务 |
| D12 | QUALITY 绿色后用户确认，完成 MEMORY；或明确取消 | 主 Agent 更新检查点并定向清理当前目录；保留其他任务与配置，旧提示不重建任务 |

验收记录保留实际完成的案例、轨迹位置、阶段序列与文件边界。未执行案例标明未执行；
任何静态断言均不得写成宿主已经证明按预期加载、停止或拦截写入。
